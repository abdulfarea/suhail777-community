# Seguranca

O SUHAIL777DEFENSE e uma ferramenta publica de leitura cautelosa. Nao envie chaves privadas, senhas, tokens, API keys, frases-semente, saldos, PII ou dados de usuario ao maintainer ou ao repositorio. O projeto nunca deve solicitar esses valores para revisar um problema.

## Como relatar

O relato privado de vulnerabilidades foi habilitado neste repositorio e confirmado pela API GitHub em 2026-10-26. Abra a pagina **Security**, use **Report a vulnerability** e siga as instrucoes apresentadas pelo GitHub. Um relato privado de vulnerabilidade tecnica nao e um canal de recuperacao de fundos; nao anexe dados financeiros pessoais ou credenciais.

Se a opcao nao estiver visivel ou deixar de estar habilitada, nao publique detalhes de exploracao, PoC perigosa, credenciais ou dados pessoais em issue, pull request ou Discussion publica. Abra uma Discussion publica apenas com uma descricao nao sensivel pedindo orientacao para um canal privado habilitado pelo maintainer, sem anexar segredos. Nao use um email inventado ou um endereco encontrado em outro lugar como canal oficial.

Se nao houver canal privado disponivel, compartilhe somente o minimo necessario para reproduzir o risco com um fixture ficticio, depois de remover identificadores e instrucoes de abuso. Uma issue publica comum nao e um canal privado.

## Escopo pratico

Relate, por exemplo, leitura inesperada de dados, vazamento de segredo por logs, bypass de modo read-only, escrita em carteira, transacao nao autorizada, dependencia comprometida ou falha que contradiga o comportamento documentado. O projeto nao promete detectar todos os riscos, fornecer auditoria, responder em prazo definido ou operar monitoramento 24 horas.

Ao testar, use uma carteira de desenvolvimento sem fundos e fixtures locais. Nao tente acessar dados de terceiros, nao envie transacoes e nao mantenha um bot ativo contra um endpoint publico.

## O que incluir sem dados sensiveis

- versao do commit ou release;
- sistema operacional e versao do Python;
- comando reproduzivel com placeholders;
- comportamento observado e comportamento esperado;
- fixture minimo e ficticio, se necessario;
- impacto tecnico sem nomes, enderecos reais ou credenciais.

A classificacao `INCONCLUSIVO` ou `unknown` nao significa `scam`. Evite alegacoes sobre pessoas, bots, reembolsos ou leis.
